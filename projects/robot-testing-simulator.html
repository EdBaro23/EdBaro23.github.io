Professional project

Robot Testing Simulator

Turns a robot's design files into a driveable virtual copy and runs it against a real ROS stack, so a design iteration can be tested before anyone manufactures it.

Type
Professional, digital division of a logistics group
Role
Developer, with the robotics team
Interfaces with
ROS, URDF robot descriptions

The problem

Manufacturing a physical prototype for every design iteration is expensive enough to slow robot development down. Simulation is the usual answer, but the robotics team had assessed the existing simulation software and found it missing what they needed.

What I built

The simulator builds a 3D copy of a warehouse robot from the design files the team already maintained, and connects it to ROS, the same open-source robot operating system running on the real hardware. The simulated robot speaks to the same stack as the physical one, so a design can be tested before it is manufactured.

Key capabilities

  • Model generation from URDF: the 3D robot is built automatically from a Unified Robotics Description Format file, so it follows the design rather than being modelled by hand.
  • Live ROS interface: connects to a running ROS instance, so the control software under test is the real thing rather than a stand-in.
  • Full motor actuation: every motor can be driven, and the model can be controlled from the keyboard for hands-on testing.
  • Object tracking with a mini-map: tracked objects appear in a map in the top-right corner, showing what the robot has registered alongside what is actually there.

Why generating from URDF mattered

A hand-built model is accurate exactly once. As soon as the mechanical design changes, the simulation is testing a robot that no longer exists, and that only surfaces when the physical prototype behaves differently. Reading the same description file as the rest of the toolchain means the simulation follows the design, and a new iteration is testable as soon as it is drawn.
